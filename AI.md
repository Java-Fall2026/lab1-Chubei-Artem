# Звіт про використання AI у лабораторній роботі №2

1. **Інструмент та ключовий запит:**
   Використовувався LLM-асистент. Первинний промпт:
   > "У мене варіант 7 (Інтернет-магазин). Перероби класи моєї предметної області з ЛР1 на використання enum OrderStatus із власним полем і конструктором, перетвори незмінні класи на record із компактним конструктором, видали зайвий згенерований код, додай два switch-вирази у StoreUtils та продемонструй усі вимоги в Main."

2. **Що AI зробив неправильно:**
   - **Спроба перетворити класи з сеттерами на record:** AI спочатку спробував зробити record для `Order` та `OrderItem`, проігнорувавши позначку ✎ у доменному профілі. Оскільки компоненти record неявно є `private final`, об'єкти record не можуть мати сеттерів для зміни стану.
   - **Застарілі виклики методів доступу:** У класах `Order` та `Main` модель продовжувала генерувати виклики `customer.getEmail()` замість згенерованих компілятором методів `customer.email()`.
   - **Синтаксис switch:** Спочатку був згенерований оператор `switch` зі старим двокрапковим синтаксисом `case ...: return ...; break;` замість компактного switch-виразу зі стрілками `case ->`.
   - **Зайва гілка default:** У switch-виразі по `OrderStatus` AI додав гілку `default`, хоча компілятор Java гарантує вичерпність при повному переборі констант enum.

3. **Що було виправлено самостійно:**
   - На `record` переведено лише клас `Customer`, бо його поля суворо незмінні. Класи `Order`, `Product` та `OrderItem` залишено звичайними класами з успадкуванням `BaseEntity`.
   - Виправлено виклики компонентів record на `customer.email()`.
   - Реалізовано два switch-вирази зі стрілками: один вичерпний по enum, другий — по категоріях для розрахунку знижки.
   - Додано обробку `valueOf` через try/catch та демонстрацію полів константи enum у `Main`.
